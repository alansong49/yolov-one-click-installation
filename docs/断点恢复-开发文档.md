# YOLO AutoInstaller 断点恢复功能开发文档

## 一、功能概述

YOLO AutoInstaller 2.0 新增了**断点恢复（Resume from Interruption）**功能。当用户在下载或部署过程中误点关闭按钮、程序意外崩溃或系统重启后，再次打开程序时能够自动检测未完成的任务，并提供继续、放弃或稍后处理三种选择。

### 1.1 核心能力

| 能力 | 说明 |
|------|------|
| **进程状态持久化** | 将部署步骤、下载进度、文件校验信息写入 JSON 状态文件，支持主路径 + AppData 兜底双存储 |
| **断点续传** | 基于 HTTP Range 请求实现权重文件断点续传，已下载的 `.part` 临时文件保留复用 |
| **步骤级跳过** | 已完成的部署步骤（如创建目录、安装 PyTorch）在恢复时自动跳过，不重复执行 |
| **文件完整性校验** | 恢复时对已下载文件进行 SHA256 校验，损坏文件自动标记重下 |
| **关闭保护** | 部署/训练/环境安装进行中时，关闭按钮弹出三选一对话框，防止误中断 |
| **后台托盘** | 支持最小化到系统托盘继续执行，完成后自动恢复窗口 |

## 二、架构设计

### 2.1 模块关系

```
main.py (GUI 层)
    ├── ResumeDialog          → 启动时恢复选择对话框
    ├── CloseConfirmDialog    → 关闭时操作选择对话框
    ├── InstallThread         → 部署线程（持有 TaskStateManager）
    └── QSystemTrayIcon       → 系统托盘（后台运行）

modules/
    ├── task_state.py         → 状态管理核心（新增）
    │   ├── sha256_of()       → 流式哈希计算
    │   └── TaskStateManager  → 状态读写、下载记录、文件校验
    │
    └── yolo_installer.py     → YOLO 部署安装器（改造）
        ├── _st_done()        → 步骤是否已完成
        ├── _st_mark()        → 标记步骤完成并持久化
        ├── _st_current()     → 设置当前步骤
        └── install()         → 支持 resume 参数跳过已完成步骤
```

### 2.2 状态文件 Schema

状态文件为 JSON 格式，主路径为程序同目录 `resume_state.json`，失败时兜底写入 `%APPDATA%\YOLO_AutoInstaller\resume_state.json`。

```json
{
  "version": 1,
  "task_type": "deploy",
  "status": "in_progress",
  "yolo_name": "YOLOv8",
  "version_info": { "key": "yolov8", "name": "YOLOv8", ... },
  "env_name": "yolov8_env",
  "python_version": "3.10",
  "pytorch_version": "2.1.0",
  "use_gpu": false,
  "run_test": true,
  "annotation_tool": "",
  "workspace_dir": "C:\\yolo_workspace",
  "completed_steps": ["创建工作目录", "创建 Conda 虚拟环境"],
  "current_step": "安装 PyTorch",
  "download": {
    "filename": "yolov8n.pt",
    "path": "C:\\yolo_workspace\\models\\yolov8n.pt.part",
    "downloaded": 52428800,
    "total": 104857600
  },
  "finished_files": [
    {
      "filename": "yolov8n.pt",
      "path": "C:\\yolo_workspace\\models\\yolov8n.pt",
      "size": 104857600,
      "sha256": "a1b2c3..."
    }
  ],
  "started_at": "2026-09-27T00:00:00",
  "updated_at": "2026-09-27T00:05:30"
}
```

### 2.3 关键设计决策

| 决策 | 原因 |
|------|------|
| **JSON 而非 SQLite** | 部署状态结构简单，JSON 读写原子性通过 `tmp + os.replace` 保证，无需引入数据库依赖 |
| **双路径存储** | 主路径（exe 同目录）便于用户查看；AppData 兜底应对无写入权限的受限环境 |
| **步骤粒度恢复** | 9 个可标记步骤覆盖部署全流程，粒度适中，既避免重复劳动又保持逻辑清晰 |
| **下载进度节流落盘** | 百分比不变且距上次 <1.5 秒时跳过写盘，避免高频 IO 影响下载速度 |
| **仅校验权重文件** | 依赖包（PyTorch 等）安装成功即视为完成，不重复校验；权重文件单文件大、易损坏，需 SHA256 校验 |
| **不删除 conda 环境** | 放弃时仅清理 `.part` 文件和已下载实体，conda 环境保留，避免用户误删后需重装 |

## 三、核心模块详解

### 3.1 modules/task_state.py

#### 3.1.1 类结构

```python
class TaskStateManager:
    STATE_VERSION = 1
    STATE_FILENAME = 'resume_state.json'

    def __init__(self):
        self.primary_path = os.path.join(get_runtime_dir(), STATE_FILENAME)
        self.fallback_path = os.path.join(
            os.environ.get('APPDATA') or os.path.expanduser('~'),
            'YOLO_AutoInstaller', STATE_FILENAME
        )
        self.path = self.primary_path
        self.state = None
        self._last_dl_save = 0.0
        self._last_dl_pct = -1
```

#### 3.1.2 核心方法

| 方法 | 职责 |
|------|------|
| `_save()` | 原子写入：先写 `.tmp` 文件，再 `os.replace` 替换；主路径失败自动切兜底路径 |
| `load()` | 主→兜底顺序读取 JSON；校验 `task_type == 'deploy'` 和 `version` 兼容性 |
| `has_pending()` | 判断是否存在 `status == 'in_progress'` 的未完成状态 |
| `begin_task(...)` | 初始化新任务状态，覆盖旧状态 |
| `set_current_step(step)` | 更新 `current_step` 字段 |
| `mark_step_done(step)` | 追加到 `completed_steps` 并保存 |
| `update_download(...)` | 更新下载进度，节流控制（1.5 秒间隔） |
| `record_finished_file(...)` | 文件下载完成后登记路径、大小、SHA256，清除 download 记录 |
| `verify_finished_files()` | 恢复时遍历 `finished_files`，校验 SHA256；失效文件从列表剔除，若权重失效同时撤销 `'下载模型权重'` 步骤标记 |
| `discard(log=None)` | 清理 `.part` 文件、`finished_files` 实体文件、状态文件；**不删除** conda 环境和源码目录 |
| `clear()` | 任务成功完成后删除状态文件 |

### 3.2 modules/yolo_installer.py 改造点

#### 3.2.1 步骤标记辅助方法

```python
def _st_done(self, step_name):
    """检查步骤是否已在历史任务中完成"""
    return step_name in self._completed

def _st_mark(self, step_name):
    """标记步骤完成，同步写入状态管理器"""
    self._completed.add(step_name)
    if self._state_mgr is not None:
        try:
            self._state_mgr.mark_step_done(step_name)
        except Exception:
            pass  # 状态写入失败不影响主流程

def _st_current(self, step_name):
    """设置当前正在执行的步骤"""
    if self._state_mgr is not None:
        try:
            self._state_mgr.set_current_step(step_name)
        except Exception:
            pass
```

#### 3.2.2 install() 方法恢复逻辑

```python
def install(self, version_info, use_gpu=False, python_version=None,
            pytorch_version=None, state_mgr=None, resume=False):
    self._state_mgr = state_mgr
    self._completed = set()

    if resume and state_mgr is not None and state_mgr.has_pending():
        self._completed = set(state_mgr.state.get('completed_steps', []))
        invalid = state_mgr.verify_finished_files()
        if invalid:
            yield {'type': 'log', 'message': f'⚠️ 检测到 {len(invalid)} 个文件损坏，将重新下载'}
```

每个部署步骤均包裹跳过逻辑：

```python
if self._st_done('创建工作目录'):
    yield {'type': 'log', 'message': '⏭️ 工作目录已创建，跳过'}
else:
    # ... 实际创建逻辑 ...
    self._st_mark('创建工作目录')
```

#### 3.2.3 可标记的 9 个步骤

| 步骤名 | 对应操作 |
|--------|----------|
| `创建工作目录` | 创建 workspace_dir、models 目录 |
| `创建 Conda 虚拟环境` | `conda create -n {env_name} python={version}` |
| `配置 pip 镜像源` | 写入 pip.ini / pip.conf |
| `安装 PyTorch` | pip 安装 torch/torchvision/torchaudio |
| `初始化数据集目录` | 创建 data/images/train 等 YOLO 数据集结构 |
| `拉取源码` | git clone YOLO 仓库 |
| `安装依赖` | pip install -r requirements.txt |
| `安装 YOLO 包` | pip install ultralytics（YOLOv8+） |
| `下载模型权重` | 下载默认权重 .pt 文件 |

### 3.3 main.py 改造点

#### 3.3.1 InstallThread 增强

- 新增 `resume` 参数，标识是否为恢复任务
- 非恢复模式：调用 `state_mgr.begin_task(...)` 初始化状态
- 恢复模式：调用 `state_mgr.load()` 加载历史状态
- `download_progress` 事件追加 `state_mgr.update_download(...)` 持久化
- 成功完成后 `state_mgr.clear()` 清除状态
- 失败/异常时保留状态，日志提示"下次打开程序可选择继续部署"

#### 3.3.2 ResumeDialog（恢复选择对话框）

启动时延迟 1.2 秒检测：

```python
QTimer.singleShot(1200, self._check_resume_task)
```

对话框三选项：

| 按钮 | 结果常量 | 行为 |
|------|----------|------|
| ▶ 继续部署 | `CONTINUE = 1` | 回填配置 → 创建 `InstallThread(resume=True)` → 从中断处继续 |
| 🗑 放弃并清理 | `DISCARD = 2` | 二次确认后调用 `state_mgr.discard()` 清理文件和状态 |
| 暂不处理 | `LATER = 0` | 关闭对话框，状态文件保留，下次启动再次提示 |

#### 3.3.3 CloseConfirmDialog（关闭确认对话框）

当检测到 `install_thread` / `env_install_thread` / `train_thread` 任一在运行时，拦截 `closeEvent`：

| 按钮 | 结果常量 | 行为 |
|------|----------|------|
| 🔽 最小化到后台继续 | `BACKGROUND = 1` | 隐藏窗口 → 系统托盘运行 → 完成自动恢复窗口 |
| 💾 关闭并保留进度 | `CLOSE_KEEP = 2` | 直接关闭程序，状态文件已持久化，下次启动可恢复 |
| 取消 | `CANCEL = 0` | 忽略关闭事件，返回主窗口 |

## 四、断点续传机制

### 4.1 既有基础

`yolo_installer.py` 的 `_download_default_weight` 方法此前已实现基础断点续传：

- 使用 `.part` 临时文件，下载完成后重命名为正式文件
- 发送 `Range: bytes={downloaded}-` 请求头
- 校验响应状态码 `206` 和 `Content-Range` 头
- 下载中断时保留 `.part` 文件，下次继续

### 4.2 本次增强

1. **状态持久化**：`download_progress` 事件实时写入 `state_mgr`，记录 `filename/path/downloaded/total`
2. **完成登记**：下载完成后调用 `record_finished_file()`，记录正式文件路径和 SHA256
3. **恢复校验**：`verify_finished_files()` 在恢复时校验已登记文件，损坏则自动重下
4. **放弃清理**：`discard()` 删除 `.part` 文件和对应正式文件，避免残留

## 五、数据一致性保障

### 5.1 原子写入

```python
def _save(self):
    tmp_path = self.path + '.tmp'
    with open(tmp_path, 'w', encoding='utf-8') as f:
        json.dump(self.state, f, ensure_ascii=False, indent=2)
    os.replace(tmp_path, self.path)  # 原子替换
```

### 5.2 SHA256 流式校验

```python
def sha256_of(path, chunk_size=1 << 20):
    """1MB 块流式计算，避免大文件内存溢出"""
    h = hashlib.sha256()
    with open(path, 'rb') as f:
        while True:
            chunk = f.read(chunk_size)
            if not chunk:
                break
            h.update(chunk)
    return h.hexdigest()
```

### 5.3 校验流程

```
恢复启动
    ↓
load() 加载状态
    ↓
verify_finished_files()
    ├── 遍历 finished_files
    ├── 检查文件是否存在
    ├── 存在 → 计算 SHA256 比对
    │       ├── 匹配 → 保留
    │       └── 不匹配 → 剔除，标记重下
    └── 不存在 → 剔除，标记重下
    ↓
返回失效文件列表
    ↓
GUI 显示黄色警告区，提示用户将重新下载
```

## 六、异常处理策略

| 异常场景 | 处理策略 |
|----------|----------|
| 状态文件损坏 | `load()` 捕获 JSONDecodeError，返回 None，视为无待恢复任务 |
| 主路径无写入权限 | `_save()` 自动切换至 AppData 兜底路径 |
| 下载中断 | `.part` 文件保留，`update_download` 记录进度，恢复时 Range 续传 |
| 文件 SHA256 不匹配 | 从 `finished_files` 剔除，撤销对应步骤标记，恢复时重新下载 |
| 部署线程异常退出 | `InstallThread.run` 的 `except` 分支保留状态文件，日志提示下次恢复 |
| 用户选择"放弃" | 二次确认后 `discard()` 清理文件，不删除 conda 环境 |
