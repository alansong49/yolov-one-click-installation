## 1. 项目概述

本工具是面向 Windows / Linux 平台的可视化图形程序，实现图形界面选择 YOLO 版本、全自动搭建 Conda 深度学习环境，用户无需手动输入任何终端命令。

**支持的部署版本**：YOLOv5、YOLOv7、YOLOv8、YOLOv9、YOLOv10、YOLO11。

**2.0 版本核心能力**：

- 全自动环境部署（Conda + PyTorch + YOLO 源码/依赖）；
- 断点恢复：部署中断后进度持久化，支持步骤级跳过、下载断点续传、SHA256 文件校验；
- 关闭保护与系统托盘后台运行；
- 一键训练（自动定位权重、实时 Epoch 进度、结果自动编号保存）；
- 标注工具管理（LabelImg / LabelMe）与编辑器集成（VSCode / PyCharm）。

## 3. 整体架构与调用流程

### 3.1 分层架构

```
GUI 界面层（main.py，PyQt6 主线程）
    │  接收用户指令、管理 5 个页签控件
    │  ResumeDialog（启动恢复）/ CloseConfirmDialog（关闭保护）/ QSystemTrayIcon（托盘）
    ↓ Qt 信号槽（log_signal / step_signal / finished_signal / download_progress_signal）
后台线程层（QThread 子线程）
    │  InstallThread（一键部署）、环境安装线程、训练/操作线程
    │  线程引用由窗口级 self._ops_threads 列表持有，finished 信号触发后自动移除（防 GC 崩溃）
    ↓ 生成器事件协议
功能核心模块（modules/）
    ├─ env_scan.py        系统环境检测
    ├─ env_installer.py   Conda / Git 安装
    ├─ conda_handler.py   Conda / pip 命令封装
    ├─ yolo_installer.py  YOLO 部署流水线（核心）
    ├─ task_state.py      断点状态持久化
    ├─ auto_test.py       自动化测试
    └─ editor_deploy.py   编辑器配置
            │
            └─ platform_utils.py  跨平台适配（Windows / Linux / macOS）
    ↓
静态配置文件 repos.yaml（6 个 YOLO 版本定义）
```

### 3.2 生成器事件协议

部署流水线以 Python 生成器实现，逐事件推送，线程层逐事件转发为 Qt 信号：

| 事件 type | 含义 | 消费方 |
|-----------|------|--------|
| `step` | 当前步骤名变更（`step` + `log` 字段） | 进度标签 + 日志面板 |
| `log` | 运行日志行（`log` 字段） | 日志面板 |
| `error` | 致命错误，流水线终止（`log` 字段） | 日志面板 + 失败弹窗；保留断点状态 |
| `success` | 部署全部成功（`log` 字段） | 成功弹窗；清除断点状态文件 |
| `download_progress` | 下载进度（`current` / `total` / `filename` / `path`） | 进度条 + ETA + 断点状态节流落盘 |
| `patches_applied` | 补丁应用计数（字典事件） | 日志统计 |

### 3.3 完整数据流

```
程序启动 → 延迟 1.2 秒检测断点状态（有则弹恢复对话框）
        → 自动环境扫描（Conda / Git / GPU）
        → 用户选择参数（版本 / Python / PyTorch / GPU / 工作目录）
        → 弹窗二次确认 → 创建 InstallThread(resume=…)
        → 线程内：TaskStateManager 建档或读档
        → installer.install(...) 生成器逐事件产出
        → 线程转发 Qt 信号 → 主线程刷新界面
        → 成功：state_mgr.clear() + 弹窗；失败：保留状态 + 提示下次可继续
```

## 5. 各模块详细功能说明

### 5.1 main.py｜GUI 主模块

**模块定位**：人机交互入口，管理窗口控件、后台线程调度、断点恢复与关闭保护交互，串联全部底层模块。

**强制规范**：所有耗时任务必须放入独立 QThread 子线程，禁止主线程执行命令，防止窗口卡死；线程必须被窗口级列表持有，防止被垃圾回收导致硬崩溃。

**页面结构**（5 个页签）：

| 页签 | 功能 |
|------|------|
| ▶ 一键部署 | 环境检测、版本/Python/PyTorch/GPU/工作目录配置、部署启动、恢复对话框入口 |
| ◆ 标注工具 | LabelImg / LabelMe 安装、卸载、启动，环境列表自动+手动刷新 |
| ⚙ 环境部署 | VSCode（全自动）/ PyCharm（半自动）项目配置生成 |
| ⚙ 训练/验证/预测/导出/视频 | 逐条命令式细分操作 |
| ◎ 一键训练 | 环境/模型选择（按系列筛选 + 全局扫描）、数据集路径填充、训练参数与实时进度 |

**关键组件**：

- `InstallThread(QThread)`：部署线程；持有 `TaskStateManager`，全新部署建档 / 恢复部署读档；转发安装器事件；成功后清除状态文件，失败/异常保留并提示"下次可继续"；
- `ResumeDialog`：启动 1.2 秒后检测到未完成任务时弹出，显示任务信息（版本、环境、中断步骤、已完成列表、下载进度百分比、损坏文件警告），提供"继续 / 放弃并清理（二次确认）/ 暂不处理"；
- `CloseConfirmDialog`：关闭窗口且有任务运行时拦截 `closeEvent`，提供"最小化到后台 / 关闭并保留进度（训练时变为终止训练）/ 取消"；
- 系统托盘：懒创建，双击恢复窗口，菜单含"打开主窗口 / 退出"；部署完成自动恢复窗口并还原 `setQuitOnLastWindowClosed(True)`；
- 下载进度处理：1 秒节流刷新，按文件名切换重置采样，速度 = Δbytes/Δt，ETA 格式化 mm:ss / h:mm:ss；
- 环境名/路径回填：恢复部署时按 `env_name` 定位版本下拉项，按 `workspace_dir` 拆分盘符（Windows）或直接匹配绝对路径（Linux）。

### 5.2 modules/platform_utils.py｜跨平台适配核心

**模块定位**：单一代码库多平台运行的基石，所有平台差异集中于此，其他模块仅调用本模块。

**主要函数**：

- `is_windows() / is_linux() / is_macos()`：系统判定；
- `get_runtime_dir()`：运行目录定位——frozen 模式取 `sys.executable` 所在目录（exe 同目录），开发模式取项目根；状态文件、缓存、日志均以此为基准；
- `get_resource_path(rel)`：资源定位——frozen 模式基于 `sys._MEIPASS`（PyInstaller 解压目录），解决打包后 `repos.yaml`、`assets/` 找不到的问题；
- `normalize_path(path)`：`normpath` 后非 Windows 将反斜杠统一为正斜杠；
- `get_available_install_locations()`：Windows 返回存在的盘符列表，Linux 返回 `~`、`/opt`、`/usr/local` 中可写者；
- `get_conda_search_paths() / get_vscode_search_paths() / get_pycharm_search_patterns() / get_git_search_paths()`：多路径探测清单；
- `get_miniconda_download_url(version)`：按平台拼接官方安装包地址。

### 5.3 modules/env_scan.py｜环境扫描模块

**模块定位**：程序初始化最先运行，探测本机基础依赖，为安装决策提供依据。

- 遍历系统常见路径与注册表（Windows）查找 conda，验证有效性后返回绝对路径；
- 执行 `git --version` 检测 Git；
- 执行 `nvidia-smi` 检测 NVIDIA 显卡与 CUDA 版本，决定 GPU/CPU 默认推荐；
- 封装通用终端执行工具，统一捕获 stdout/stderr/返回码/异常；
- 输出：conda 路径、Git 状态、显卡状态、扫描日志。

### 5.4 modules/env_installer.py｜环境安装模块

**模块定位**：自动安装 Conda 与 Git，解决"干净系统首次使用"场景。

**镜像源策略**（多源顺序重试）：

| 组件 | 源顺序 |
|------|--------|
| Anaconda | 北京大学镜像 → 清华镜像 → 官方源（`_build_anaconda_urls`） |
| Miniconda | 清华镜像 → 中科大镜像 → 官方源（`_build_miniconda_urls`） |
| Git（Windows 五级） | ① 系统 winget → ② npmmirror 镜像下载官方安装包（当前用户免权限安装，失败转系统级）→ ③ 自动安装 winget（SHA256 校验 + 损坏重试 + 依赖补齐）→ ④ conda 安装（defaults → 清华 conda-forge，stderr 同步输出）→ ⑤ 本地安装包兜底 |
| PyTorch | 上海交大镜像 → PyTorch 官方源 |

- Git 安装成功后自动将 `cmd` 目录加入进程 PATH 并验证（用户级/系统级均检查），保证程序内 `git clone` 立即可用；
- 安装路径写入 `conda_install_record.json` 供后续定位；
- Windows 静默安装 `.exe`，Linux 静默执行 `.sh`。

### 5.5 modules/conda_handler.py｜Conda 命令封装模块

**模块定位**：统一封装所有 conda / pip 操作，规避 Windows 无法直接 `conda activate` 的经典问题。

**核心约定**：

- 环境内执行统一使用 `conda run -n <env> --no-capture-output`（`--no-capture-output` 避免子进程输出缓冲导致日志延迟），环境名加引号；
- 设置 `PYTHONUNBUFFERED / PYTHONIOENCODING / PYTHONUTF8` 环境变量，避免中文路径与日志乱码；
- pip 命令一律 `python -m pip`（强制绑定环境内解释器），加 `--progress-bar raw` 强制纯文本进度。

**主要接口**：`create_env()`、`env_exists()`、`get_env_python_version()`、`list_envs()`、`get_python_path()`、`config_pip_mirror()`、`install_torch_cuda121() / install_torch_cpu()`、`pip_install() / pip_install_requirements() / pip_install_editable() / pip_upgrade_base()`。

**环境删除**（强制清理三段式）：

1. `conda env remove` 常规删除；
2. 强制清目录（L387-417）：解除只读属性、重试 3 次应对文件占用，覆盖 `conda env remove` 清不掉的 pip 未登记文件；
3. 权限不足时 UAC 提权删除（L419-442）。删除成功标准为**文件夹物理消失**，需双重确认；base 环境受保护禁止删除。

**残留目录识别**（L307-344）：`conda-meta` 缺失但目录存在的环境判定为残留，列表中以橙色"xxx（残留）"行显示，Python 版本列显示"—"，支持一键删除。扫描与删除均在后台线程执行，界面不卡顿。

### 5.6 modules/yolo_installer.py｜YOLO 部署流水线（业务核心）

**模块定位**：读取 repos.yaml 区分两种部署路线，自动化执行整套部署；生成器事件协议的数据源头。

**部署步骤**（9 个可断点标记步骤）：

| 步骤 | source 模式 | pip 模式 |
|------|-------------|----------|
| 创建工作目录 | ✅ | ✅ |
| 创建 Conda 虚拟环境（含版本一致性拦截） | ✅ | ✅ |
| 配置 pip 镜像源 | ✅ | ✅ |
| 安装 PyTorch（含 site-packages 写权限检测、Python 3.8 自动降级 2.4.1） | ✅ | ✅ |
| 初始化数据集目录 | ✅ | ✅ |
| 拉取源码（多镜像 × 每源 2 次重试） | ✅ | — |
| 安装依赖（requirements / editable + setuptools） | ✅ | — |
| 安装 YOLO 包（ultralytics） | — | ✅ |
| 下载模型权重 | ✅ | ✅（放工作目录根） |

**关键实现**：

- **环境版本一致性拦截**：环境已存在时检测实际 Python 版本，与选择不符立即报错并指引删除旧环境，防止包版本不匹配；
- **写权限检测**：安装 PyTorch 前在环境 site-packages 写测试文件，不可写时报错指引（管理员运行或改装用户目录），防止 pip 静默改装到用户目录破坏隔离；
- **权重下载 `_download_default_weight`**：多镜像顺序尝试；`.part` 临时文件 + `Range: bytes=` 请求 + 206/Content-Range 校验实现断点续传；镜像不支持 Range 时自动从头下载；短读视为中断保留断点；完成后 `os.replace` 落正式文件并登记 SHA256（`record_finished_file`）；
- **weights_only 补丁**：PyTorch ≥ 2.6 默认 `weights_only=True` 导致旧版权重加载失败，部署时向环境写入 `sitecustomize.py` 全局覆盖所有 `torch.load` 入口；
- **纯权重文件处理**：converted / GELAN 等无结构权重训练时自动定位仓库内 `models/detect/xxx.yaml` 附加 `--cfg` 参数，yaml 不存在安全跳过；
- **模型识别**：按权重文件名（去 `.pt`）与内置官方模型名清单精确匹配；跨系列模型在日志中提示所属系列。

### 5.7 modules/task_state.py｜断点状态管理模块（2.0 新增）

**模块定位**：部署任务断点状态的唯一读写入口，支撑断点恢复全部功能。

**状态文件**：`resume_state.json`，主路径为运行目录，兜底路径为 `%APPDATA%\YOLO_AutoInstaller\`（Windows）或 `$XDG_DATA_HOME` / `~/.local/share/YOLO_AutoInstaller/`（Linux/macOS）。

**核心方法**：

| 方法 | 职责 |
|------|------|
| `_save()` | 临时文件 + `os.replace` 原子写入；主路径失败自动落兜底 |
| `load()` | 主→兜底顺序读取，校验 `task_type == 'deploy'` |
| `has_pending()` | 存在 `status == 'in_progress'` 的待恢复任务 |
| `begin_task(...)` | 新任务建档（覆盖旧状态） |
| `mark_step_done() / set_current_step()` | 步骤完成标记 / 当前步骤记录 |
| `update_download(...)` | 下载进度节流落盘（百分比未变且 <1.5 秒跳过） |
| `record_finished_file(...)` | 登记完成文件（路径/大小/SHA256） |
| `verify_finished_files()` | 恢复时校验文件一致性，损坏剔除并撤销"下载模型权重"标记 |
| `discard(log)` | 放弃清理：删除 `.part`、正式残留、已登记实体与状态文件；**不删** conda 环境与源码目录 |
| `clear()` | 部署成功后删除状态文件 |

状态文件 schema 与完整恢复流程详见 [docs/断点恢复-开发文档.md](docs/断点恢复-开发文档.md)。

### 5.8 modules/auto_test.py｜自动化测试模块

**模块定位**：部署结束后自动验证环境可用性，避免"表面安装成功、实际运行报错"。

- source 模式：在仓库内运行 `detect.py` 图片推理；
- pip 模式：执行简短 Python 代码加载模型推理；
- 自动生成/复用测试图片与 Arial 字体（自动从 `C:\Windows\Fonts\Arial.ttf` 复制到 YOLO 配置目录，规避 HTTP 308 字体下载错误）；
- 识别报错类型（模块缺失 / CUDA 异常 / 字体问题），推送结果与修复建议至日志面板。

### 5.9 modules/editor_deploy.py｜编辑器部署模块

**模块定位**：将部署好的 Conda 环境接入常用编辑器。

- VSCode：生成 `.vscode/settings.json`（解释器路径）与 `launch.json`（调试配置），全自动；
- PyCharm：生成 `.idea` 项目配置（含 Conda 解释器提示），首次打开需手动确认，半自动；
- 支持多环境切换与一键在编辑器中打开项目。

### 5.10 repos.yaml｜静态配置文件

**模块定位**：集中管理 YOLO 版本参数，新增版本只改配置不改代码。

**存储字段**（每个版本）：

| 字段 | 说明 |
|------|------|
| `name` | 界面展示名称 |
| `mode` | `source`（源码部署）或 `pip`（库安装） |
| `env_name` | 虚拟环境名称（如 `yolov8_env`） |
| `folder_name` | 源码克隆目录名（source 模式） |
| `git_urls` / `git_url` | 源码仓库地址列表（多镜像顺序重试） |
| `pkg_name` | pip 包名（pip 模式，如 `ultralytics`） |
| `install_method` | `requirements` 或 `editable` |
| `python_version` / `recommended_pytorch` | 推荐版本 |
| `test_weight` / `release_repo` / `release_tag` | 默认权重文件名与 GitHub Release 来源 |
| `yolo_series` | 系列标识（训练页按系列筛选权重） |

**路径解析兼容**：frozen 模式经 `sys._MEIPASS` 定位打包内 repos.yaml，开发模式按模块 `__file__` 向上两级推算——两者差异曾在打包版引发"配置文件不存在"，已由 `get_resource_path` 统一解决。

## 6. 断点恢复机制详解

完整设计文档见 [docs/断点恢复-开发文档.md](docs/断点恢复-开发文档.md)，此处仅列机制要点：

1. **持久化**：JSON + 临时文件 + `os.replace` 原子替换；双路径兜底；
2. **步骤级恢复**：9 个步骤完成标记，恢复时跳过已完成步骤；
3. **下载断点续传**：`.part` 保留 + HTTP Range + 206 校验；进度节流落盘（1.5 秒）；
4. **一致性保障**：完成文件登记 SHA256，恢复时流式校验（1MB 分块），损坏自动重下；
5. **GUI 交互**：启动恢复对话框（继续/放弃/暂不处理）、关闭保护（后台/保留进度/取消）、托盘后台与完成自动恢复；
6. **放弃清理边界**：只删下载产物与状态文件，conda 环境与源码目录保留（避免误删有效成果）。

## 7. 完整开发实施步骤

### 阶段 1：前期环境准备

1. 本地安装 Python 3.10+、Miniconda3、Git；
2. 创建独立 venv：`python -m venv venv`；
3. 安装依赖：`pip install PyQt6 pyyaml requests pyinstaller`。

### 阶段 2：模块分步开发与单元测试（按依赖顺序）

1. **platform_utils.py**：先确定运行目录与资源定位约定（frozen / 源码双模式），独立验证；
2. **env_scan.py**：独立脚本测试 conda / git / GPU 识别；
3. **conda_handler.py**：单独测试环境创建、`conda run` 执行 pip、删除与残留清理；
4. **env_installer.py**：测试多镜像下载与静默安装（建议在干净虚拟机）；
5. **yolo_installer.py + repos.yaml**：分别测试 source / pip 两条流水线；
6. **GUI 骨架**：页面布局与按钮绑定（先打印测试日志，不接真实逻辑）；
7. **线程对接**：QThread + 信号槽，日志实时回显；线程持有引用列表防 GC；
8. **auto_test.py**：接入流水线末尾；
9. **task_state.py + 断点恢复**：状态读写单测 → 安装器步骤标记/跳过 → GUI 对话框/托盘/ETA；
10. **训练页与操作页**：权重扫描缓存、训练进度、`--no-capture-output` 对齐；
11. **整体联调**：逐个 YOLO 版本完整走通部署 → 测试 → 训练。

### 阶段 3：测试规范

- 静态检查：`py_compile` 全量编译 + `pyflakes` 零警告；
- GUI 自动化：`QT_QPA_PLATFORM=offscreen` 环境变量 + 类级 monkeypatch 打桩（`show_about` / `auto_scan_env` / `start_global_model_scan`），测试结尾 `os._exit(0)` 防 offscreen 析构崩溃；
- 长命令注意：PowerShell 内联 `python -c` 复杂引号会被剥离，必须写临时 `.py` 文件执行。

## 8. 核心难点与解决方案

| 难点 | 解决方案 |
|------|----------|
| GUI 执行安装时窗口无响应 | 所有命令执行放 QThread 子线程，主线程只刷新界面；线程由窗口级列表持有防 GC 崩溃 |
| Windows 终端无法激活 conda 环境 | 全程统一 `conda run -n <env> --no-capture-output`，摒弃 activate |
| GitHub 克隆缓慢/超时 | repos.yaml 配置多镜像地址（清华/Gitee/gitclone），每源重试 2 次，失败自动切换 |
| exe 打包后读取 yaml/资源失败 | frozen 模式用 `sys._MEIPASS` 定位（`get_resource_path` / `_default_config_path`），打包配置中加入 repos.yaml 与 assets |
| 程序异常闪退 | 全量 try/except 捕获，错误输出日志面板并落盘 log 文件 |
| PyTorch ≥ 2.6 加载旧版权重失败（weights_only） | 部署时写入 sitecustomize.py 全局补丁覆盖 torch.load |
| Python 3.8 与 PyTorch 2.5+ 不兼容 | 安装前版本检测，自动降级到 2.4.1 并日志说明 |
| Conda 装在受保护目录导致 pip 写入失败 | 安装 PyTorch 前做 site-packages 写权限检测，明确报错指引 |
| `conda env remove` 残留 pip 文件 | 三段式删除：常规删除 → 强制清目录（去只读 + 3 次重试）→ UAC 提权；以文件夹物理消失为成功标准 |
| 权重下载中断需从头重下 | `.part` 保留 + HTTP Range 断点续传 + 206/Content-Range 校验 |
| 部署中断后进度丢失 | task_state.py 断点状态持久化（本手册第 6 节） |
| 中文日志乱码 | 子进程注入 PYTHONUNBUFFERED / PYTHONIOENCODING / PYTHONUTF8 |
| 字体下载 HTTP 308（Python 3.8 urllib 不跟随 308） | 部署时从系统字体目录复制 Arial.ttf 到 YOLO 配置目录 |
| 全盘扫描模型过慢 | 跳过 Anaconda3/miniconda3、Program Files、AppData 等系统目录；结果先写内存缓存再落盘，保存失败兜底 AppData 并日志提示 |

## 9. 软件运行前置条件

**最终用户**：

- Windows 10/11（64 位）或 Linux（Ubuntu/CentOS/Fedora/Arch/openSUSE 等）；
- Conda、Git **无需预装**（程序可自动安装）；
- GPU 部署需 NVIDIA 显卡（程序自动检测，无卡自动走 CPU 路线）；
- 可选网络：全程需要网络下载组件；权重下载支持断点续传，弱网可用。

**开发者**：

- Python 3.10+、PyQt6、PyYAML、requests、PyInstaller；
- Windows 打包需 venv 内含 PyInstaller；Linux 打包由 `Linux一键安装.sh` / `linux/build.sh` 自动准备。

## 10. 成品操作流程

1. 打开程序，等待自动环境扫描（或点击重新扫描）；
2. 「一键部署」页选择 YOLO 版本、Conda 类型、Python/PyTorch 版本、GPU/CPU、安装位置与工作目录；
3. 点击「一键安装部署」并确认；
4. 观察日志与进度（下载显示速度与预计剩余时间）；部署中关闭窗口会弹出三选一保护；

## 11. 打包与发布流程

### Windows

```bash
build.bat
# 或
venv\Scripts\python.exe -m PyInstaller YOLO_AutoInstaller.spec --noconfirm --clean
# 产物：dist\YOLO_AutoInstaller_2.0.exe（单文件，含 repos.yaml 与 assets）
```

打包要点：`--windowed` 关闭控制台；spec 中 datas 包含 `repos.yaml` 与 `assets/`；新版本打包**不覆盖旧 exe**（产物名带版本号）。

### Linux

```bash
bash Linux一键安装.sh        # 依赖 + 打包 + 快捷方式一条龙
# 或仅打包
bash linux/build.sh          # 产物：dist/YOLO_AutoInstaller_2.0
```

打包要点：`--add-data "repos.yaml:."` 与 `"assets:assets"` 必须携带；快捷方式固定命名 `YOLO_AutoInstaller.desktop` 不随版本变化。

### 发布 GitHub Release

1. 提交并推送代码：`git push origin main`；
2. 打标签：`git tag -a v2.0 -m "…" && git push origin v2.0`；
3. 用 GitHub API 创建 Release（独立新标签，**不覆盖历史 Release**），上传 exe 资产并撰写发布说明（可参考 `upload_release.py` 的 ghapi 实现）；
4. 验证：`GET /releases?per_page=20` 确认历史 Release 完整、资产可下载。
